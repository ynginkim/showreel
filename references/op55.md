# op55 음악 연동

showreel이 op55 출력을 사용하는 방법과 제작 절차는 이 문서에서 관리한다. 실행 명령은 [SKILL.md 5단계](../SKILL.md#5-오디오를-먼저-만든다)에 있다.

## op55 출력 계약

op55 파일 형식과 격자 복구 방법의 정본은 설치된 `<resolve-op55-tools>/references/output-contract.md`다. `<resolve-op55-tools>`는 해당 skill의 base directory다. 설치본에 이 파일이 없으면 참조 미확인으로 기록한다. 아래 showreel 동작은 이 저장소 코드와 대조했다. 제작자가 수행할 수동 절차는 별도 절로 구분했다.

## 설치와 경로

op55는 `op55-mode`, `op55-compose`, `op55-render`, `op55-verify`, `resolve-op55-tools`, principle 3개를 함께 설치한다. 설치는 Node 22.20.0 이상, op55 렌더만 하면 Node 18 이상이 필요하다.

```bash
npx skills@1.7.4 add ynginkim/op55 -a claude-code    # 전역 설치는 -g 추가
node "<resolve-op55-tools>/scripts/setup.mjs"       # 기본 사운드뱅크 88MB
```

옛 단일 스킬에서 이전할 때는 위 명령으로 새 스킬을 설치한 뒤 `npx skills@1.7.4 remove op55`로 옛 사본을 제거한다. 전역 설치였으면 `npx skills@1.7.4 remove -g op55`를 쓴다. 악보와 bank 캐시는 제거 대상이 아니다.

음악 단계에서는 `op55-compose`, `op55-render`, `op55-verify`의 `SKILL.md`를 직접 읽는다. showreel 내부에서 `op55-mode`를 실행하지 않는다. 세 work skill이 읽는 `resolve-op55-tools`에서 scripts 절대 경로와 필요한 도구·bank를 확인한다. `$S`는 `<showreel>/scripts`, `$O`는 `<resolve-op55-tools>/scripts`의 확인한 절대 경로다. 악보 API·편곡·음악 검수 기준은 각각 `op55-compose/references/score.md`, `op55-compose/references/arranging.md`, `op55-verify/references/verify.md`를 읽는다.

`preflight.py`는 `OP55_SCRIPTS`가 있으면 그 경로만 검사한다. 없으면 다음 위치의 `resolve-op55-tools/scripts`를 순서대로 찾는다.

1. 실행 중인 showreel 폴더 옆.
2. 현재 작업 폴더부터 상위 폴더마다 `.claude/skills`, `.agents/skills` 순서.
3. `~/.claude/skills`, `~/.agents/skills`.

후보 경로는 심볼릭 링크를 해석한 뒤 `render.mjs`, `setup.mjs`, `verify.py`가 모두 있는지 확인한다. 옛 `op55/scripts` 구조와 그 구조를 가리키는 링크는 선택하지 않고 이전 안내를 stderr에 출력한다. 명시한 경로가 잘못돼도 다른 설치본으로 대체하지 않는다. 선택한 경로의 `setup.mjs --check`로 기본 사운드뱅크 유무를 표시한다. 경로를 이미 확인했다면 preflight에 `OP55_SCRIPTS="$O"`를 넘겨 같은 도구를 사용한다.

믹스 검증에는 `verify.py`에 `--mix timeline.json --mix-py "$S/mix.py"`를 넘긴다. 이 경로는 이번 showreel 설치본의 믹서를 가리켜야 한다. 검증 WAV와 `timeline.json`의 `music.file`이 같은 파일인지 확인한다.

## showreel이 읽는 값

| 입력 | 실제 동작 |
| --- | --- |
| `script.json`의 `music.file` | `timeline.py`가 화면 envelope를 계산할 오디오이고, 생성된 `timeline.json`을 읽는 `mix.py`가 믹스할 오디오다. 상대 경로는 각각 script·timeline 파일의 폴더 기준이다. `analysis.file`로 오디오를 선택하지 않는다 |
| `timeline.py --music-analysis`와 `music.analysis` | 값이 있는 CLI 인자가 우선한다. 상대 경로는 `script.json`의 폴더 기준이다. 지정한 파일이 없으면 다른 분석 파일로 대체하지 않아 음악 큐가 생성되지 않는다 |
| 분석의 `downbeats`, `hits` | 배열 순서대로 `bar1…`, `music.hit1…` 큐를 만든다. 두 배열과 `beats`에 `music.start`를 더해 영상 시각으로 옮긴다 |
| 화면 envelope | `analysis.energy`를 사용하지 않는다. `music.file`의 WAV에서 0.05초 간격으로 다시 계산해 `reel/timeline.js`의 `music.energy`에 쓴다. 장면의 `REEL.level(t, 'music')`가 이를 읽는다 |
| 믹스의 `music` | 소스를 -16 LUFS로 재정규화하고 `start` 위치에 배치한다. 영상 시각의 `automation`으로 dB를 보간하고, 나레이션 기반 주파수별 duck과 `gain_db`를 적용한다. `--music-db`, `--duck`은 설정값보다 우선한다. op55 master 목표와 showreel 최종 믹스 목표는 별개다 |
| `music.meta.json`의 `credits[].credit` | 제작자가 영상 크레딧에 옮기는 입력이다. `timeline.py`·`mix.py`·`finish.py`에는 이를 자동으로 넣는 처리가 없다 |

분석의 hit가 어느 음악 사건에서 생기는지와 WAV·JSON의 형식은 op55 출력 계약을 따른다. showreel은 일부 누락 값에 기본값을 쓰므로, 실행 성공만으로 파일 계약 전체를 검사했다고 보고하지 않는다.

## 프로젝트 제작 절차

아래는 제작자가 수행할 절차다. showreel이 악보의 `gaps`를 수정하거나 재렌더할 장면을 자동으로 고르지 않는다.

1. `concept.md`의 구간을 큐 시트에 옮기고 `op55-compose`로 악보를 쓴다. `$O/examples/`에서 가까운 예시를 고를 수 있다. 프로젝트 폴더에서 렌더해 `audio/music/`에 WAV·analysis·meta를 둔다. `music.file`과 `music.analysis`를 이 출력에 연결한다. op55가 쓴 분석의 격자를 사용하고 `music_tools.py analyze`로 다시 검출하지 않는다.
2. `op55-verify`로 렌더를 검사한 뒤 `timeline.py`로 음악 큐를 만든다. 장면 경계는 `barN`을 우선 사용한다. hit 배열의 항목이 추가되거나 빠지면 뒤의 `music.hitN` 번호가 바뀐다.
3. 나레이션을 배치한 `timeline.json`의 `vo[].start`·`end`에서 발화하지 않는 구간을 구한다. 1.2초 이상 빈틈을 악보의 `gaps`에 적고 편곡에 사용한 뒤 다시 렌더한다. 1.2초는 이 제작 절차의 선택 기준이며 `timeline.py`의 자동 추출 기능이 아니다.
4. **같은 격자는 필요조건일 뿐이다.** 새 beats·downbeats가 기존 값과 1ms 이내로 맞는지 비교하고, 화면이 소비하는 `music.hitN`·`music.start`·음악 envelope를 확인한다. `reel/scenes.js`와 장면 모듈에서 cue·hit 배열·`REEL.level(t, 'music')` 및 그 값으로 만든 pulse를 찾아 비교한다. 새 WAV로 `timeline.py`를 다시 실행해야 새 envelope가 생긴다.
5. 소비하는 값이나 크레딧 화면이 바뀐 장면을 다시 렌더한다. 조각별 기존 결과가 있으면 `render_pieces.py --only`로 해당 조각을 갱신하고 이어 붙인다. 해당 값이 같은 장면은 재사용하고 근거를 남긴다. 음악이 바뀌면 `mix.py`·`finish.py`·QA는 다시 실행한다. 크레딧 문구도 이때 화면에 수동 반영한다.
6. 나레이션이 있으면 명시한 믹서로 test mix를 검사한다. exit 0만으로 통과라고 쓰지 않는다. 누락 파일, 믹서 미발견, 빈 나레이션 표, 다른 `music.file` 경고는 중단 또는 미측정으로 기록한다. 나레이션이 없는 곡의 mix margin은 N/A다. PNG는 직접 열어 확인하고, 나머지 음악 판정은 `op55-verify`의 기준을 따른다.

## 완성 영상의 음악 교체

기존 영상의 격자를 새 악보에 보존한다. 격자를 되찾는 방법은 [op55 출력 계약](#op55-출력-계약)의 격자 복구 안내를 읽는다. 이 문서에는 복구 방법을 복제하지 않는다.

화면에서는 위 제작 절차의 소비 값 비교를 수행한다. hit 번호, 음악 시작 위치, 음악에 반응하는 장면과 크레딧 화면의 변경 여부를 보고 재렌더 범위를 정한다. 격자만 같다는 이유로 모든 장면을 재사용하지 않는다.

## 납품 보고

- 나레이션 줄의 전체 수·✓ 수와 최소 voice-over-bed 여유를 적는다. 현재 믹서는 300~4000Hz 대역에서 줄마다 측정하며 9 dB 이상을 ✓로 표시한다. 실제 나레이션과 합성 톤 fixture를 구분한다.
- `credits[].credit` 문구와 영상에 반영한 위치를 적는다. 비어 있으면 비어 있다고 보고한다.
- 재사용한 장면과 그 근거, 다시 렌더한 장면을 적는다.
- 미달·미측정 항목과 열어 본 PNG를 적는다. "음악은 수치와 그림으로 확인했으며, 사람이 직접 들어 봐야 합니다"라고 요청한다. 사람의 청취·시청은 수행 전까지 미확인으로 남긴다.

## 코드 대조 근거

아래 줄 번호는 이 문서를 추가할 때의 소스 기준이다. 제작 절차와 납품 보고는 사람이 수행하는 운영 규칙이며 코드가 자동으로 보장하지 않는다.

| --- | --- |

| 분석 선택 우선순위·상대 경로·음악 큐·시작 위치 | [timeline.py](../scripts/timeline.py) 62–64, 90–101행 |
| WAV 선택·envelope 계산과 저장 | [timeline.py](../scripts/timeline.py) 36–54, 198–218행 |
| 장면의 cue·bar·beat·음악 envelope 소비 | [engine.js](../assets/engine/engine.js) 251–279행 |
